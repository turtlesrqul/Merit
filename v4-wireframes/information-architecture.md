# Information Architecture

## V4 Structure

V4 separates Merit into four sides:

- Public side.
- Student side.
- Recruiter side.
- Admin/internal side.

The IA should keep one mental model consistent:

> Work becomes proof. Proof becomes signal. Signal creates opportunity.

## Public Side

### Landing Page

Purpose: explain the proof-based hiring thesis and route students/recruiters.

Primary paths:

- Build your passport.
- Review proof as recruiter.
- Browse proof preview.

Key content:

- "Proven by work."
- Proof card to shortlist product scene.
- Recruiter and student value propositions.
- Examples of strong proof cards.

### Public Student Profiles

Rename mental model: public passport.

Sections:

- Candidate identity.
- Target role.
- Strongest proof.
- Evidence-backed skills.
- Proof timeline.
- CV/contact.
- Availability or role interest.

### Public Project Pages

Rename mental model: proof page.

Sections:

- Artifact preview.
- What was built.
- Candidate contribution.
- Skills demonstrated.
- Evidence attached.
- Outcome/impact.
- Role relevance.
- Gaps or missing proof.

### Public Discovery Preview

Purpose: show proof-first browsing without turning the product into a social feed.

Filters:

- Target role.
- Skill.
- Project type.
- Evidence level.
- Recency.

## Student Side

### Onboarding

Start with target role and strongest proof.

Do not start with profile completion.

Steps:

1. Choose target role.
2. Pick strongest project.
3. Explain contribution.
4. Attach evidence.
5. Publish first proof card.
6. Complete passport basics.

### Dashboard

Purpose: help students improve proof quality.

Primary modules:

- First proof card status.
- Passport readiness.
- Evidence gaps.
- Recruiter-view preview.
- Recent activity.

### Profile Builder

Rename mental model: passport builder.

Fields:

- Name.
- Contact.
- Target roles.
- Headline.
- Bio as evidence context, not personal essay.
- CV.
- Portfolio links.

### Project Proof Builder

The main student creation tool.

Sections:

- Role targeted.
- Project title.
- Candidate contribution.
- What was built.
- Evidence upload/link.
- Skills demonstrated.
- Outcome.
- Tools used.
- Team/solo.
- Timeline.
- Difficulty.
- Gaps.

### Evidence Upload

Supports:

- Screenshots.
- PDFs.
- GitHub links.
- Figma links.
- Live demos.
- Videos.
- Testimonials.
- Case studies.
- Decks/documents.

### Proof Passport

Student-owned public object.

Includes:

- Strongest proof first.
- Evidence-backed skills.
- Role readiness view.
- Contact and CV.
- Public share link.

### Role Readiness View

Purpose: show whether the passport proves the role the student wants.

Signals:

- Proof cards mapped to target role.
- Evidence quality levels.
- Missing evidence.
- Suggested improvements.

## Recruiter Side

### Recruiter Onboarding

Start with hiring need.

Steps:

1. Tell Merit what role you are hiring for.
2. Define required skills/signals.
3. Choose evidence preferences.
4. Review matched proof.

### Search

Search should be role/evidence first.

Inputs:

- Role.
- Skills.
- Evidence level.
- Project type.
- Availability.
- School/program if needed.
- Keywords.

### Discovery

This is not a generic gallery. It is an evidence search workspace.

Layout:

- Left role/filter rail.
- Center candidate proof results.
- Right evidence preview.

### Shortlist

Purpose: track candidates worth interviewing.

Fields:

- Candidate.
- Target role fit.
- Strongest proof.
- Evidence level.
- Notes.
- Contact status.
- Comparison state.

### Candidate Evidence View

This is the recruiter version of a public passport.

Prioritize:

- Why this candidate may be relevant.
- Strongest matching proof.
- Evidence quality.
- Contribution and outcome.
- Missing proof.
- Contact/save/compare.

### Role Brief

The recruiter-defined source of truth.

Fields:

- Role title.
- Hiring context.
- Must-have skills.
- Nice-to-have skills.
- Evidence preferences.
- Location/availability.
- Seniority/internship level.

### Evidence Comparison

Compare 2-4 candidates by:

- Role fit.
- Strongest proof.
- Skills demonstrated.
- Evidence quality.
- Outcomes.
- Gaps.
- Recruiter notes.

### Saved Candidates

Saved candidates are not likes. They are review queue items.

States:

- Saved.
- Comparing.
- Shortlisted.
- Contacted.
- Archived.

## Admin/Internal Side

### User Management

Basic user inspection and moderation.

### Project Review

Review public proof for spam, abuse, broken links, and unsafe content.

### Featured Candidates

Curate strong proof examples for student onboarding and recruiter demos.

### Evidence Quality Review

Optional internal scoring/rubric used for PMF research, not shown as absolute truth.
