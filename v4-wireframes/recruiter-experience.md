# Recruiter Experience

## Core Question

> Who should I interview, and why?

Every recruiter surface should answer that question faster than a resume, LinkedIn profile, or scattered portfolio link.

## Experience Principles

### Speed

Recruiters should understand role relevance in seconds.

Design for:

- Dense but readable cards.
- Evidence summaries.
- Quick preview panel.
- Shortlist actions always near decision context.

### Confidence

Recruiters need enough proof to defend a decision.

Design for:

- Evidence levels.
- Outcome/context.
- Contribution clarity.
- Missing-proof notes.

### Evidence Clarity

Do not make recruiters infer everything from a beautiful project image.

Each result should say:

- What was built.
- What the candidate did.
- What skills it shows.
- What evidence exists.
- What gaps remain.

### Comparison

Early-career candidates often look similar on resumes. Comparison should make evidence differences visible.

### Trust

Trust comes from honest uncertainty as much as strong evidence.

Show gaps. Avoid magic AI language.

## Recruiter Workspace Layout

Recommended layout:

```text
+----------------------+--------------------------------+-------------------------+
| Role brief + filters  | Candidate evidence results     | Selected evidence view  |
|                      |                                |                         |
| Frontend Intern      | 1. Amira, FE intern            | Why relevant           |
| Must: React, UI      |    Strong evidence match       | Strongest proof        |
| Evidence level 3+    |    Shipped Next dashboard      | Evidence level         |
| Availability         |    Missing: usage metrics      | Gaps                   |
|                      |                                | Save / Compare / Open  |
+----------------------+--------------------------------+-------------------------+
```

## Search Result Card Priorities

Each recruiter result card should prioritize:

1. Candidate name.
2. Target role fit.
3. Strongest evidence.
4. Projects that match role.
5. Skills demonstrated.
6. Evidence level.
7. Gaps / missing evidence.
8. Actions: view evidence, save, compare.

Avoid generic student profile cards first.

## Candidate Evidence Profile

Sections:

- Candidate identity.
- Role-specific evidence summary.
- Strongest matching proof.
- Evidence-backed skills.
- Proof timeline.
- Gaps and review caveats.
- CV/contact.
- Recruiter notes.

Primary CTA:

> Shortlist

Secondary CTAs:

> Save, compare, contact

## Role Brief

The role brief should be the recruiter's starting point.

Fields:

- Role title.
- Hiring goal.
- Must-have skills.
- Nice-to-have skills.
- Evidence preferences.
- Availability.
- Location.
- Notes.

Prompt:

> What proof would make you want to interview someone?

## Comparison View

Compare candidates by evidence, not vibes.

Rows:

- Role fit summary.
- Strongest proof.
- Evidence level.
- Skills demonstrated.
- Outcome.
- Contribution clarity.
- Missing proof.
- Contact availability.
- Recruiter notes.

## Empty States

### No Role Brief

> Create a role brief so Merit can search for relevant proof.

CTA:

> Create role brief

### No Results

> No candidates match this evidence filter yet.

Actions:

- Lower evidence level.
- Remove one required skill.
- Request curated candidates.

### No Shortlist

> Save candidates worth interviewing here.

CTA:

> Search evidence

## Recruiter Trust Copy

Use:

- "Evidence found."
- "Missing evidence."
- "May be relevant."
- "Strong evidence match."
- "Needs review."

Avoid:

- "Best candidate."
- "AI recommends hiring."
- "Verified fit."
- "Guaranteed match."
