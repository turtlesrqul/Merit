# Student Experience

## Core Question

> How do I prove I can do the role I want?

The student experience should make the answer feel achievable, specific, and serious.

## Student UX Principles

### Strongest Proof First

Do not ask students to complete a long profile before they understand what Merit is for.

Start with:

> Build your first proof card.

### Role Intent Before Project Fields

Students should choose a target role before writing project content. This lets Merit prompt them for the right evidence.

### Evidence Without Endless Forms

The proof builder should feel guided, not bureaucratic.

Use progressive disclosure:

1. Target role.
2. Project and contribution.
3. Evidence.
4. Skills.
5. Outcome.
6. Gaps and publish.

### Beautiful, But Recruiter-Readable

The student side should still feel portfolio-like and motivating. But every beautiful artifact needs context that recruiters can use.

## Student Onboarding

Flow:

1. Choose target role.
2. Pick strongest project.
3. Explain personal contribution.
4. Attach proof.
5. Publish proof card.
6. Add passport basics.

Microcopy:

- "What role do you want your work to prove?"
- "Pick the project that best shows you can do that role."
- "What did you personally own?"
- "Attach something a recruiter can inspect."
- "Add the outcome, even if it is small."

## Proof Builder

Layout:

- Left: guided fields.
- Right: live recruiter preview.
- Bottom: evidence checklist.

Fields:

- Target role.
- Project title.
- Proof claim.
- Candidate contribution.
- Project type.
- Evidence links/uploads.
- Skills demonstrated.
- Outcome.
- Tools used.
- Team or solo.
- Timeline.
- Difficulty.

## Passport Dashboard

Purpose:

Help students keep proof recruiter-readable.

Sections:

- First proof status.
- Passport readiness.
- Evidence gaps.
- Target role match.
- Public preview.
- Suggestions.

Do not make readiness feel like a moral judgment. It measures evidence completeness.

## Public Passport

The passport should feel like a credible hiring dossier.

Hierarchy:

1. Candidate identity and target role.
2. Strongest proof card.
3. Evidence-backed skills.
4. Proof timeline.
5. CV/contact.
6. Additional artifacts.

## Improvement Suggestions

Examples:

- "Add a live link or PDF to move this proof from Level 1 to Level 3."
- "Clarify your contribution. Recruiters need to know what you personally owned."
- "Add an outcome: user count, grade, client comment, award, or measurable result."
- "Your target role is UX intern. Add process evidence, not only final screens."

## Student Emotional Goal

Students should feel:

- "My work counts."
- "I know how to explain what I built."
- "Recruiters can understand this."
- "I can improve my proof without guessing."

## Avoid

- Endless profile forms.
- Generic bio-first onboarding.
- Social popularity as the main validation.
- "Incomplete" language that shames weak proof.
- AI copy that invents achievements.
